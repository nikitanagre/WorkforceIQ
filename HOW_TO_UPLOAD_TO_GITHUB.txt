# HOW TO UPLOAD WorkforceIQ TO GITHUB
# Step-by-step guide (beginners welcome!)

===========================================================
STEP 1: Install Git (if not already installed)
===========================================================
Windows  → Download from: https://git-scm.com/download/win
Mac      → Run in terminal: brew install git
Ubuntu   → Run: sudo apt install git

Check it works:
  git --version


===========================================================
STEP 2: Create a GitHub Account
===========================================================
Go to: https://github.com
Click "Sign Up" → create free account
Verify your email


===========================================================
STEP 3: Create a New Repository on GitHub
===========================================================
1. Click the "+" icon (top right) → "New repository"
2. Repository name: WorkforceIQ
3. Description: Intelligent Workforce Scheduling & Productivity Analytics System
4. Set to: Public  ← (so interviewers can see it!)
5. DO NOT check "Add README" (we already have one)
6. Click "Create repository"
7. COPY the URL shown — it looks like:
   https://github.com/YOUR_USERNAME/WorkforceIQ.git


===========================================================
STEP 4: Set Up Git in Your Project Folder
===========================================================
Open terminal / command prompt.
Navigate to your WorkforceIQ folder:

  cd path/to/WorkforceIQ

Initialize git:
  git init

Set your identity (first time only):
  git config --global user.name "Your Name"
  git config --global user.email "your@email.com"


===========================================================
STEP 5: Add All Files & Make First Commit
===========================================================
  git add .
  git commit -m "Initial commit: WorkforceIQ full-stack project"


===========================================================
STEP 6: Connect to GitHub & Push
===========================================================
  git remote add origin https://github.com/YOUR_USERNAME/WorkforceIQ.git
  git branch -M main
  git push -u origin main

When prompted:
  Username: your GitHub username
  Password: your GitHub Personal Access Token
  (GitHub no longer accepts passwords — see Step 6b)


===========================================================
STEP 6b: Create a Personal Access Token (PAT)
===========================================================
1. GitHub → Settings → Developer Settings → Personal Access Tokens
2. Click "Tokens (classic)" → "Generate new token"
3. Name: WorkforceIQ upload
4. Expiration: 90 days
5. Check "repo" scope
6. Click Generate → COPY the token (save it somewhere!)
7. Use this token as your "password" when pushing


===========================================================
STEP 7: Verify on GitHub
===========================================================
Go to: https://github.com/YOUR_USERNAME/WorkforceIQ
You should see all your files and the README displayed!


===========================================================
STEP 8: Future Updates (after making changes)
===========================================================
  git add .
  git commit -m "Describe what you changed"
  git push


===========================================================
USEFUL GIT COMMANDS
===========================================================
git status              → see what files changed
git log --oneline       → see commit history
git diff                → see exact changes
git branch feature-x    → create a new branch
git checkout feature-x  → switch to that branch
git merge feature-x     → merge branch into main
git pull                → get latest changes from GitHub


===========================================================
INTERVIEW TIPS — What to say about Git
===========================================================
✓ "I used Git for version control throughout the project"
✓ "I made meaningful commits at each feature milestone"
✓ "The project is hosted on GitHub at: github.com/YOUR_USERNAME/WorkforceIQ"
✓ "I followed feature-branch workflow"
✓ "I used .gitignore to exclude sensitive files like .env and *.db"
